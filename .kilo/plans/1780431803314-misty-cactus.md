# Make Primary Buttons Colored

## Problem
The project's Button component (`src/components/ui/Button.tsx`) uses semantic Tailwind classes like `bg-primary text-primary-foreground hover:bg-primary/90`, and the Tailwind config (`tailwind.config.ts`) defines color aliases like `background: 'hsl(var(--background))'`. However, none of these CSS variables (`--primary`, `--background`, `--foreground`, etc.) are defined anywhere in the project. All primary buttons are currently transparent.

## Solution
Add CSS variable definitions to the project's `src/styles/tailwind.css` file.

## Changes

### 1. Add CSS variables to `src/styles/tailwind.css`

Add a `@layer base` block inside the existing `@layer base` block with CSS custom properties:

```css
@layer base {
  :root {
    --primary: #0f688a; /* teal-blue brand color */
    --primary-foreground: #ffffff;
    --secondary: #64748b;
    --secondary-foreground: #ffffff;
    --background: #ffffff;
    --foreground: #0f172a;
    --muted: #f1f5f9;
    --muted-foreground: #64748b;
    --border: #e2e8f0;
    --input: #e2e8f0;
    --ring: #0f688a;
    --radius: 0.5rem;
  }

  .dark {
    --primary: #5eead4;
    --primary-foreground: #0f172a;
    --secondary: #475569;
    --secondary-foreground: #f8fafc;
    --background: #0f172a;
    --foreground: #f8fafc;
    --muted: #1e293b;
    --muted-foreground: #94a3b8;
    --border: #1e293b;
    --input: #1e293b;
    --ring: #5eead4;
  }
}
```

This will make the existing semantic classes (`bg-primary`, `text-primary-foreground`, etc.) produce a teal-blue primary color that matches the CRM's likely brand.

The button default variant will then produce a colored button instead of being transparent.

## Impact
- All existing `<Button>` usage (31 instances across the codebase) will automatically get colored primary buttons
- All `<Badge variant="default">` usage (in `Badge.tsx`) will also receive colored styling
- No code changes required in components — the semantic Tailwind classes already exist
