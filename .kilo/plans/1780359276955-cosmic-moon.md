# E2E Testing Plan for Aqua CRM

## Overview

This plan outlines the e2e test coverage needed for the Aqua CRM application. The existing test suite covers authentication, protected routes, dark mode, and basic view loading. This plan adds comprehensive test coverage for the core CRUD operations, navigation, and key features.

## Current Test Coverage (existing)

| Feature | File | Status |
|---------|------|--------|
| Login | `tests/e2e/login.spec.ts` | Basic login flow, validation |
| Registration | `tests/e2e/register.spec.ts` | Registration flow, validation |
| Password Reset | `tests/e2e/password-reset.spec.ts` | Form validation, success state |
| Protected Routes | `tests/e2e/auth-protected-routes.spec.ts` | Redirects, authenticated access |
| Dark Mode | `tests/e2e/dark-mode.spec.ts` | Toggle, persistence |
| View Loading | `tests/e2e/dark-mode.spec.ts` (All Views) | Basic view rendering |

## Missing Test Coverage

### Priority 1: Core CRUD Operations

#### Tasks
- **Task List View**: Test kanban/list toggle, task cards rendering, kanban board display
- **Create Task**: Fill task form (title, priority, status, description), submit, verify creation
- **Edit Task**: Navigate to task detail, edit through form, verify updates
- **Delete Task**: Confirm delete dialog appears, delete task, verify removal
- **Task Detail View**: View task details, status, priority, subtasks, dependencies

#### Contacts
- **Contact List View**: Test contact list rendering, contact cards, search functionality
- **Create Contact**: Fill contact form (first name, last name, email, phone), submit, verify creation
- **Edit Contact**: Navigate to contact edit form, modify fields, save
- **Contact Detail View**: View contact information, verify display
- **Delete Contact**: Delete contact and verify removal

#### Companies
- **Company List View**: Test company list rendering, search functionality
- **Create Company**: Fill company form (name, industry, website, address), submit, verify creation
- **Edit Company**: Navigate to company edit form, modify fields, save
- **Company Detail View**: View company information, verify display
- **Delete Company**: Delete company and verify removal

#### Activities
- **Activity Timeline**: Render activity list, verify display
- **Create Activity**: Fill activity form, submit, verify creation
- **Filter Activities**: Test activity type filtering, sort by date/type/title

### Priority 2: Navigation & Interaction

#### Dashboard
- Verify dashboard loads with summary cards (Total Contacts, Open Tasks, Activities This Week, Active Deals)
- Verify charts render (task status breakdown, activity type breakdown)
- Verify recent activity section displays correctly

#### Reports
- Navigate to reports page, verify tabs load (Tasks, Contacts, Activities, Pipeline)
- Tab switching functionality
- Export functionality (CSV format selection, export download)

#### Search
- Global search input renders correctly
- Saved filters display functionality
- Advanced filters section renders

### Priority 3: Navigation & Flow

#### Sidebar Navigation
- Sidebar renders correctly with all menu items
- Clicking navigation items navigates to correct pages
- Active route highlighting

#### Breadcrumbs/Back Navigation
- Back button on detail pages navigates correctly
- Edit form cancel button navigates back correctly
- Delete confirmation dialog works

#### Loading States
- Skeleton loading states display correctly on list views
- Loading states on API operations

### Priority 4: Form Validation & Error Handling

#### Contact Form Validation
- Required field validation (first name, last name, email)
- Email format validation
- Invalid field highlighting

#### Company Form Validation
- Required field validation (company name)
- Industry selection validation

#### Task Form Validation
- Required field validation (title)
- Parent task validation for subtasks
- Dependency validation (mixing start-to-start and finish-to-finish)
- Status/priority selection

#### Error States
- API error messages display correctly
- Error states on list views
- Error handling on form submissions

### Priority 5: Edge Cases & Integration

#### Task Dependencies
- Adding/removing dependencies
- Subtask creation with parent task selection

#### Activity Form
- Contact selection in activity form
- Activity type selection validation
- Activity date/duration validation

#### Multi-step Workflows
- Create contact → view detail → navigate to company → create company → return to contacts
- Create task → edit task → delete task

## Test Patterns

All tests should follow the existing pattern using Playwright:

```typescript
import { test, expect } from '@playwright/test';
import { login, setupTestEnvironment } from '../fixtures/setup';

test.describe('Feature Name', () => {
  test.beforeEach(async ({ page }) => {
    await setupTestEnvironment(page);
  });

  test('test description', async ({ page }) => {
    await login(page);
    // test steps
  });
});
```

## Notes

- All tests use MSW (Mock Service Worker) for API mocking via `src/mock-msw/handlers.ts`
- Tests run against the dev server with `pnpm dev`
- Existing test fixtures (`login`, `setupTestEnvironment`) should be reused
- Follow existing test style: Playwright's `test.describe`, `test.beforeEach`, `test('name', fn)` pattern
