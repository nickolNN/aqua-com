## Agent Roles

- **Frontend tasks** should be done by a **frontend-specialist agent**
  - Expertise: React 19, TypeScript, Redux Toolkit, React Query, Tailwind CSS, shadcn/ui
  - Responsibilities: Component creation, store management, API integration, UI styling

- **Backend tasks** should be done by a **code agent**
  - Expertise: Go, Gin, GORM, PostgreSQL, Redis, REST API design
  - Responsibilities: API endpoints, business logic, data models, migrations, tests

## Testing Requirements

- **All code must have 100% unit test coverage**
- Tests must be checked after each code suggestion
- Backend: Go testing package with table-driven tests (go test ./...)
- Frontend: Jest with React Testing Library (pnpm test)
- Run coverage checks after each change: `go test -cover ./...` and `pnpm test -- --coverage`

## Review Process

- **All code must go through a three-stage review process before acceptance:**

### Stage 1: Code Skeptic
- Question code decisions: Why this approach? Why not simpler alternative?
- Challenge assumptions about requirements, architecture, or implementation
- Identify potential edge cases, missing requirements, or design flaws
- Ask: "Is there a simpler way?" "Is this over-engineered?" "Does this handle all edge cases?"

### Stage 2: Code Simplifier
- Review code for simplicity and clarity
- Remove unnecessary complexity, redundant code, or over-abstracted patterns
- Suggest simpler alternatives while preserving functionality
- Ensure code follows the KISS principle - should be readable and maintainable

### Stage 3: Code Reviewer
- Verify code quality, naming conventions, and style consistency
- Check that tests cover all code paths (100% coverage requirement)
- Validate API responses match the documented format
- Ensure security best practices (parameterized queries, CSRF protection, etc.)
- Confirm the code meets all requirements from the architect's plan
- **Lint rules must be strictly obeyed:**
  - Backend: `golangci-lint run` passes with no errors or warnings
  - Frontend: `pnpm lint` passes with no errors
  - Frontend: `pnpm lint:fix` runs automatically to fix any remaining issues
  - All code must follow the project's naming conventions (kebab-case for files, camelCase for variables)
  - Code must be properly typed (TypeScript for frontend, Go types for backend)
  - No unused imports, variables, or functions

## Output

A clean, concise AGENTS.md (~100 lines) that accurately reflects the project's actual tech stack and conventions, consistent with DEVELOPMENT.md and ARCHITECTURE.md, with explicit 100% test coverage requirement.
