# Plan: Strict Plan Completion Algorithm

## Goal

Make the algorithm for completing plans stricter by defining clear completion criteria, verification gates, and approval requirements.

## Current Problem

The current plan completion algorithm (documented in `AGENTS.md` under "Plans → Plan & Orchestration") is vague:
- No explicit definition of what constitutes "completing" a step
- Missing explicit approval requirements before moving to next step
- No quality gates or verification criteria
- No mechanism for marking plan as complete
- No strategy for delivering good quality features/phases incrementally

## Proposed Changes

### 1. Update AGENTS.md: Define Step Completion Criteria

Add explicit completion criteria to the "Plan & Orchestration" section:

**Completion Requirements:**
- **Step must pass all verification steps**: Each step has implicit verification criteria (code compiles, tests pass, lint passes)
- **Explicit approval required**: Agent must request human approval before proceeding to the next step
- **No partial steps**: A step is only considered complete when ALL sub-items in the step file are fulfilled
- **Phase completion**: A phase is complete only when ALL steps in the phase are marked complete
- **Test-first development**: Where possible, write unit tests before implementation code (TDD approach)

**Approval Checklist per Step:**
1. Code compiles without errors (`go build` / `npm build`)
2. Unit tests pass (`go test ./...` / `pnpm test`)
3. No lint errors (`golangci-lint run` / `pnpm lint`)
4. Human approves the step result before next step begins

### 2. Unit Test-First Development Strategy

When possible, start development with unit tests first (TDD approach):

**Test-First Process:**
1. **Identify testable unit**: Determine what unit/function can be tested independently
2. **Write unit test first**: Write the test that describes expected behavior before implementation
3. **Implement code**: Write minimal code to satisfy the test
4. **Verify test passes**: Run tests to confirm implementation meets requirements
5. **Refactor if needed**: Ensure test still passes after refactoring

**Test Coverage Requirements:**
- **All code must have 100% unit test coverage where possible**
- Backend: Go table-driven tests (`go test ./...`) with coverage check (`go test -cover ./...`)
- Frontend: Jest with React Testing Library (`pnpm test`)
- **Run test coverage after each step**: `go test -cover ./...` / `pnpm test -- --coverage`
- No step is complete until tests pass and coverage is verified

### 2. Add Plan Completion Verification Section

Add to AGENTS.md:

```markdown
## Plan Completion Verification

| Check | Requirement | Command |
|-------|-------------|---------|
| Build | Code compiles | `go build ./...` / `npm run build` |
| Tests | All tests pass | `go test -cover ./...` / `pnpm test -- --coverage` |
| Lint | No lint errors | `golangci-lint run` / `pnpm lint` |
| Approval | Human approves step | Manual verification |

## Plan Completion Criteria

A plan is considered complete when:
- All phases are marked complete in `plans/PLAN_PROGRESS.md`
- All steps within each phase pass verification checks
- Final review by human confirms all requirements met

## Step Completion Definition

A step is complete when:
1. All sub-items (e.g., "9.1", "9.2", etc.) in the step file are implemented
2. Unit tests written before implementation (where possible)
3. Code compiles and builds without errors
4. Tests pass with 100% coverage
5. No lint errors remain
6. Human has approved the step

## Plan Marking

The plan file (`.kilo/plans/*.md`) must be updated with:
- Goal summary
- Changes required (files modified)
- Step breakdown (what steps were executed)
- Agent roles used
- Testing requirements met
- Review process summary
- Final state: plan complete | plan partial | plan in progress
```

### 3. Delivery Strategy: Quality Over Speed

The goal is to deliver good quality features/phases incrementally, not do everything at once:

**Per-Phase Delivery Strategy:**
1. **Focus on one phase at a time**: Complete all steps in a phase before moving to the next
2. **Test-first per step**: Write unit tests before implementation code (where possible)
3. **Quality gates per phase**: Build + tests + lint + human approval before proceeding
4. **Incremental delivery**: Each phase delivers a working, testable subset of functionality
5. **No rush to completion**: Prioritize quality over speed - ensure each step passes all verification before moving on

**Per-Step Execution Strategy:**
1. **Plan first**: Read the step file, understand all sub-items before execution
2. **Write unit tests first** (where possible): Identify testable units and write tests before implementation code
3. **Implement code**: Write implementation to satisfy the tests (TDD)
4. **Execute one sub-item at a time**: Complete each sub-item (e.g., "9.1", "9.2") before moving to the next
5. **Verify each sub-item**: Confirm it works before proceeding
6. **Run verification**: Build + test (with coverage) + lint after step completes

### 4. Add Phase-Level Gates

Add a gate mechanism:
- Before starting a new phase, verify the previous phase's steps are complete
- Each phase gate requires: build passes + tests pass + approval

### 3. Add Plan File Format

Require plans to include explicit completion tracking:
- Goal summary

- Verification results
- Final state marker

### 4. Add Pre-Step Verification

Before each step begins:
- Confirm previous step's completeness
- Check if any prerequisites are met (e.g., database schema ready before API implementation)
- Verify build is clean (no pending errors from previous steps)

### 4. Add Pre-Step Verification

Before each step begins:
- Confirm previous step's completeness (or initial step)
- Check if any prerequisites are met (e.g., database schema ready before API implementation)
- Verify build is clean (no pending errors from previous steps)

### 5. Plan-Before-Execution Requirement

Each step must be planned before execution in plan mode:
1. **Review step file**: Read the step's sub-items (e.g., "9.1", "9.2", etc.) from `plans/phase*/step_*.md`
2. **Plan execution strategy**: Break each sub-item into concrete actions before running commands
3. **Verify prerequisites**: Confirm any dependencies (models, migrations, endpoints) exist before implementing
4. **Execute planned steps sequentially**: Follow the plan, verify each sub-item before moving to next
5. **Record verification**: After completion, confirm all sub-items are fulfilled

### 6. Add Step Verification After Implementation

After each step completes:
- Verify all implementation criteria from step file
- Run build/test/lint
- Record verification results
- Mark step complete in PLAN_PROGRESS.md before proceeding
