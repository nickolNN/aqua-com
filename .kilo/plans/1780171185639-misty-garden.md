# Plan: Phase 1 - Foundation & Infrastructure

## Goal

Set up the foundational infrastructure for Aqua CRM: backend Go module, frontend React project, database schema, and core GORM models. This phase establishes the base layer upon which all subsequent phases build.

## Phase Overview

| Phase | Name | Steps | Status |
|-------|------|-------|--------|
| 1 | Foundation & Infrastructure | 4 | Not Started |

## Step Breakdown

### Step 1: Backend Infrastructure Setup (**BE**)

**Plan file:** `plans/phase01-foundation-infrastructure/step_1.md`

**Steps:**
1.1 Initialize Go module in `src/backend/` with `go mod init`
1.2 Add dependencies: Gin, GORM, PostgreSQL driver, Redis driver, JWT, bcrypt
1.3 Create project directories: `src/backend/src/{config,routes,controllers,services,models,repositories,middleware}`
1.4 Configure PostgreSQL connection in `src/backend/src/config/database.go` using GORM
1.5 Configure Redis connection in `src/backend/src/config/redis.go`
1.6 Configure Gin engine configuration in `src/backend/src/config/gin.go`

**Implementation notes:**
- Use Gin framework for HTTP server
- Use GORM for ORM/Database access
- Add PostgreSQL driver (`gorm.io/driver/postgres`)
- Add Redis driver (`github.com/go-redis/redis`)
- Add JWT (`github.com/gin-contrib/jwt`)
- Configure database connection with environment variables
- Set up Redis connection pool configuration
- Configure CORS middleware in Gin

**Verification:**
- `go build ./...` in `src/backend/`
- `go test -cover ./...` in `src/backend/`
- `golangci-lint run` in `src/backend/`

### Step 2: Frontend Infrastructure Setup (**FE**)

**Plan file:** `plans/phase01-foundation-infrastructure/step_2.md`

**Steps:**
2.1 Initialize React 19 project with TypeScript + Vite in `src/frontend/`
2.2 Install and configure Tailwind CSS
2.3 Install and configure shadcn/ui components
2.4 Set up Redux Toolkit: create store, configure slices (initial structure)
2.5 Set up React Query: create React Query client provider
2.6 Configure API base URL and interceptors

**Implementation notes:**
- Use Vite for build tooling (faster dev server)
- Install Tailwind CSS v3 with PostCSS
- Configure shadcn/ui with Radix primitives
- Set up Redux Toolkit with slices for: auth, contacts, companies, tasks, activities
- Configure React Query with proper retry/error handling
- Set up API base URL from environment variables
- Add Axios interceptors for auth token injection and error handling

**Verification:**
- `cd src/frontend && npm run build`
- `cd src/frontend && npx tsc --noEmit` (TypeScript type check)
- `cd src/frontend && npx eslint . --ext .js,.ts,.vue`
- `cd src/frontend && pnpm test` (unit tests)

### Step 3: Database Schema & Migrations (**BE**)

**Plan file:** `plans/phase01-foundation-infrastructure/step_3.md`

**Steps:**
3.1 Create migration files for: users, companies, contacts, tasks, activities, task_dependencies, audit_logs, webhooks
3.2 Implement GORM migration runner in `src/backend/src/migrations/`
3.3 Run initial migration to create all tables

**Migration models:**
- `users`: id, email, password_hash, role, created_at, updated_at
- `companies`: id, name, industry, website, address, custom_fields
- `contacts`: id, first_name, last_name, email, phone, company_id, custom_fields
- `tasks`: id, title, description, status, priority, due_date, assigned_to, custom_fields
- `activities`: id, type, title, description, contact_id, date, duration, custom_fields
- `task_dependencies`: id, task_id, predecessor_id, successor_id, created_at
- `audit_logs`: id, user_id, action, entity_type, entity_id, created_at
- `webhooks`: id, url, events, is_active, created_at

**Verification:**
- `go build ./...` in `src/backend/`
- `go test -cover ./...` in `src/backend/`
- `golangci-lint run` in `src/backend/`

### Step 4: Core GORM Models (**BE**)

**Plan file:** `plans/phase01-foundation-infrastructure/step_4.md`

**Steps:**
4.1 Implement User model with fields: id, email, password_hash, role, created_at, updated_at
4.2 Implement Company model with fields: id, name, industry, website, address, custom_fields
4.3 Implement Contact model with fields: id, first_name, last_name, email, phone, company_id, custom_fields
4.4 Implement Task model with fields: id, title, description, status, priority, due_date, assigned_to, custom_fields
4.5 Implement Activity model with fields: id, type, title, description, contact_id, date, duration, custom_fields
4.6 Implement task_dependencies model for predecessor/successor relationships

**Implementation notes:**
- All models should include GORM tags for proper database mapping
- Implement soft deletes where appropriate (deleted_at field)
- Add proper relationships (BelongsTo, HasMany, BelongsToMany)
- Use proper naming conventions (snake_case for database columns)

**Verification:**
- `go build ./...` in `src/backend/`
- `go test -cover ./...` in `src/backend/`
- `golangci-lint run` in `src/backend/`

## Plan Execution Rules

### Phase Restriction

Each agent is restricted to working on only one phase at a time. This ensures focused work and prevents an agent from jumping between phases.

#### Rules

1. **Single-Phase Restriction**: An agent must complete all steps within a phase before moving to the next phase
2. **No Cross-Phase Overlap**: An agent cannot start work on phase N+1 until all steps in phase N are marked complete
3. **Agent Handoff**: Once a phase is complete, the appropriate agent(s) for the next phase begin work
4. **Verification**: Agent assignment is tracked via the step tags (**BE** / **FE**) in `plans/PLAN_PROGRESS.md`

## Plan Completion Criteria

A plan is considered complete when:
- All phases are marked complete in `plans/PLAN_PROGRESS.md`
- All steps within each phase pass verification checks
- Final review by human confirms all requirements met
