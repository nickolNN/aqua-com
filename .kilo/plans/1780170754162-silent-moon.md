# Plan: TypeScript Error Watching

## Goal

Add a requirement to watch and fix TypeScript errors during frontend development to catch type issues early and maintain code quality.

## Problem

Currently, TypeScript errors are only caught at build time (`tsc` or `npm run build`). During active frontend development, type errors can accumulate without immediate feedback, leading to:
- Silent type issues in production
- Deferred type work that compounds over time
- Inconsistent typing across components

## Proposed Changes

### Update AGENTS.md

Add TypeScript error watching to the existing frontend development requirements:

**Add to AGENTS.md > Plan Completion Verification section:**
- Type check passes (`tsc --noEmit`) / No TypeScript errors

**Add to AGENTS.md > Testing Requirements section:**
- TypeScript type check passes with no errors (`tsc --noEmit`)

**Add to AGENTS.md > Step Completion Criteria:**
- TypeScript type check passes with zero errors

### Implementation Steps

#### Step 1: Add TypeScript Type Check to Verification

Add `tsc --noEmit` to all frontend verification checks:
- Build verification: `tsc --noEmit && (go build ./... || npm run build)`
- Add to the verification table as a frontend-specific requirement
- Add to step completion criteria as a frontend requirement

#### Step 2: Add TypeScript Type Check Command

Add a script to package.json (if not present):
```json
"scripts": {
  "typecheck": "tsc --noEmit"
}
```

#### Step 3: Integrate into Development Workflow

- Frontend agents must run `tsc --noEmit` before marking a step complete
- TypeScript errors must be fixed during development, not deferred
- No TypeScript errors allowed in committed code

## Verification

- Run `tsc --noEmit` to verify no type errors
- Ensure frontend builds successfully with type checking enabled

## Agent Phase Restriction

Each agent is restricted to working on only one phase at a time. This ensures focused work and prevents an agent from jumping between phases.

### Rules

1. **Single-Phase Restriction**: An agent must complete all steps within a phase before moving to the next phase
2. **No Cross-Phase Overlap**: An agent cannot start work on phase N+1 until all steps in phase N are marked complete
3. **Agent Handoff**: Once a phase is complete, the appropriate agent(s) for the next phase begin work
4. **Verification**: Agent assignment is tracked via the step tags (**BE** / **FE**) in `plans/PLAN_PROGRESS.md`

### Implementation

Add a phase restriction rule to AGENTS.md:
- **Phase Restriction**: Each agent is restricted to working on one phase at a time
- **No Phase Overlap**: Agents cannot work on multiple phases simultaneously
- **Explicit Handoff**: Agents must wait for approval and completion before moving to the next phase
