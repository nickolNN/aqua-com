# Aqua CRM Design Recommendations - Implementation Plan

## Overview

This plan addresses design recommendations from the design review of the Aqua CRM application. The recommendations fall into three priority tiers, each with specific actionable items.

## Phase 1: High-Priority Components

### 1.1 Card Component Integration

**Current state:** Views use hardcoded divs with `bg-white rounded-md border` instead of the Card component.

**Files to modify:**
- `src/views/DashboardView.tsx` — Replace hardcoded summary card divs with `<Card>` components
- `src/views/CompaniesView.tsx` — Replace company list wrapper with Card
- `src/views/ContactsView.tsx` — Replace contact list wrapper with Card
- `src/views/TaskDetailView.tsx` — Replace task detail div with Card component
- `src/views/ContactDetailView.tsx` — Replace contact detail div with Card component
- `src/views/CompanyDetailView.tsx` — Replace company detail div with Card component
- `src/views/ReportsView.tsx` — Replace report sections with Card component
- `src/views/TaskForm.tsx` — Replace form wrapper with Card component
- `src/views/ContactForm.tsx` — Replace form wrapper with Card component
- `src/views/CompanyForm.tsx` — Replace form wrapper with Card component

**Changes:**
```tsx
// Before:
<div className="bg-white border rounded-md p-6">
  {/* content */
</div>

// After:
<Card>
  <CardHeader><CardTitle>...</CardTitle></CardTitle>
  <CardDescription>...</CardDescription>
  <CardContent>{/* content */}</CardContent>
  <CardFooter>{/* content */}</CardFooter>
</Card>
```

**Implementation details:**
- Card component already exists in `src/components/ui/Card.tsx` with full semantic structure (Card, CardHeader, CardTitle, CardDescription, CardContent, CardFooter).
- Replace hardcoded divs with `<Card>` wrapper.
- Use `<CardHeader>`, `<CardTitle>`, `<CardDescription>`, `<CardContent>` for proper semantic structure.
- Ensure consistent spacing with the Card's built-in padding.

### 1.2 Button Component Integration

**Current state:** Most buttons use raw `<button>` with hardcoded `bg-blue-600 text-white rounded-md` styles instead of the Button component.

**Files to modify:**
- `src/views/DashboardView.tsx` — SummaryCard buttons (if any)
- `src/views/CompaniesView.tsx` — "Create Company" link, "Quick Add" button
- `src/views/ContactsView.tsx` — "Create Contact" link, "Quick Add" button
- `src/views/TaskDetailView.tsx` — "Edit Task" link
- `src/views/TaskForm.tsx` — "Create Task"/"Update Task" button
- `src/views/ContactDetailView.tsx` — "Edit Contact" link
- `src/views/ContactForm.tsx` — "Create Contact"/"Update Contact" button
- `src/views/CompanyDetailView.tsx` — "Edit Company" link
- `src/views/CompanyForm.tsx` — "Create Company"/"Update Company" button
- `src/views/ReportsView.tsx` — "Export Report" button

**Changes:**
```tsx
// Before:
<button className="px-4 py-2 bg-blue-600 text-white rounded-md hover:bg-blue-700">
  Create Company
</button>

// After:
<Button variant="default" size="default">
  Create Company
</Button>
```

**Implementation details:**
- Button component already exists in `src/components/ui/Button.tsx` with variants (`default`, `secondary`, `outline`, `ghost`, `link`) and sizes (`default`, `sm`, `lg`, `icon`).
- Replace hardcoded buttons with `<Button>` component.
- Use `variant="default"` for primary actions, `variant="secondary"` for secondary actions, `variant="outline"` for outlined actions.
- Use `size="sm"` for small actions, `size="default"` for primary actions.
- Links should use `variant="link"` when used as buttons.

### 1.3 Input Component Integration

**Current state:** Forms use raw `<input>` and `<textarea>` with hardcoded Tailwind styles.

**Files to modify:**
- `src/views/TaskForm.tsx` — Title, assigned_to, description fields
- `src/views/ContactForm.tsx` — First name, last name, email, phone, company_id fields
- `src/views/CompanyForm.tsx` — Name, website, address fields
- `src/views/SearchView.tsx` — Search input
- `src/views/LoginView.tsx` — Email, password fields
- `src/views/RegisterView.tsx` — Name, email, password, confirmPassword fields
- `src/views/PasswordResetView.tsx` — Email field

**Changes:**
```tsx
// Before:
<input
  id="title"
  name="title"
  type="text"
  value={formData.title}
  onChange={handleChange}
  required
  className="w-full px-3 py-2 border border-gray-300 rounded-md focus:outline-none focus:ring-2 focus:ring-blue-500"
/>

// After:
<Input
  id="title"
  name="title"
  type="text"
  value={formData.title}
  onChange={handleChange}
  required
/>
```

**Implementation details:**
- Input component already exists in `src/components/ui/Input.tsx` with proper focus states and disabled states.
- Replace raw inputs with `<Input>` component.
- Replace textarea elements with a new `<Textarea>` component (or reuse Input).
- Select elements should be replaced with a new `<Select>` component or reuse existing Input.

### 1.4 Badge Component Integration

**Current state:** Task status/priority badges use inline inline styles (`bg-blue-500 text-white`) instead of the Badge component.

**Files to modify:**
- `src/views/TaskDetailView.tsx` — Status and priority badges
- `src/components/charts/BarChart.tsx` — Chart hover tooltips
- `src/components/charts/PieChart.tsx` — Chart labels

**Changes:**
```tsx
// Before:

// After:

</Badge>
```

**Implementation details:**
- Badge component already exists in `src/components/ui/Badge.tsx` with `destructive` variant.
- Add `variant` prop mapping for status/priority colors.
- Add a `variant` mapping for task status (`default`, `warning`, `success`, `destructive`) and priority (`default`, `high`, `urgent`).
- Replace hardcoded `bg-*` classes with appropriate variant classes.

### Phase 2: Layout Components

- **`src/stores/settingsSlice.ts`** — Add theme state management:
  - Add `theme` slice (values: `'light' | 'dark'`).
  - Add `toggleTheme` action that toggles CSS class on `document.documentElement` (or `document.body`).
  - Read initial theme from localStorage or system preference (`prefers-color-scheme`).
  - Persist theme choice in localStorage.

- **`src/components/layout/Sidebar.tsx`** — Make sidebar collapsible on mobile:
  - Add state for `isOpen` (open/closed).
  - On mobile (≤768px), sidebar becomes a slide-out drawer with dark backdrop overlay.
  - Add a hamburger menu button that toggles sidebar state.
  - Ensure backdrop overlay uses dark semi-transparent background.

- **`src/components/layout/Header.tsx`** — Add user profile dropdown:
  - Add user avatar component (initials or icon) in the header.
  - Add dropdown with options: Settings, Profile, Logout.
  - Use Radix UI Dialog/Popover for dropdown.

- **`src/components/layout/MainLayout.tsx`** — Wire everything together:

## Summary

This plan addresses all high-priority design recommendations from the design review. The implementation is structured in phases, starting with component integration (Card, Button, Input, Badge) and moving to UX improvements (Dark mode, Skeleton loading states, Responsive sidebar) and finally to enhancements (Form validation, Toast notifications, Chart improvements).
