## Findings

### F1 (minor) — verifier's rich-task link check is timing-dependent and fails under load

- **Where:** `scripts/verify-consistency.mjs:161-184` — the check
  "TaskDetailModal link actions use shared Button link variant".
- **What broke:** after `page.goto(rich-task URL)` (which waits for the full
  `load` event), the script sleeps a fixed 600 ms (line 164) and then counts
  link-variant buttons. Under dev-server load the detail modal's link buttons
  render later than 600 ms, so the count is 0 and the check fails with `[]` —
  a false failure of an app that is actually consistent.
- **Reproduction:** run `pnpm test` (46 tests, ~49 s) to load the dev server,
  then immediately run `node scripts/verify-consistency.mjs`. In this session
  it failed twice that way (14:31 and 14:35) and passed 11/11 once the server
  was responsive again (14:41). A targeted probe measured the "View parent
  task" button appearing ~240 ms after navigation when the server is
  responsive — inside the 600 ms window only when the server is fast.
- **Fix:** replace the fixed sleep at line 164 with a Playwright auto-wait,
  e.g. `await page.getByRole('button', { name: 'View parent task' }).waitFor()`,
  and/or make the check tolerant when the current task data contains no
  rich task (parent + dependency) instead of failing.
