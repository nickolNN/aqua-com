# Resolve — iteration 1

## What was done

This is a self-retry of a crashed resolve run. The previous session had already
completed the core work — all 5 design-consistency fixes and the before/after
screenshot evidence — before it timed out. This session picked up from the
partial state, verified the fixes, repaired the regressions the previous
session had introduced, and finished the self-checks.

### Carried over from the crashed session (verified in place)

1. **ConfirmDialog** (`src/components/ui/ConfirmDialog.tsx`) — replaced the
   hand-rolled fixed-position dialog with the shared `Dialog` primitive
   (Radix-based glass panel, blurred backdrop, entry animation, focus trap,
   Esc-to-close). `max-w-md` keeps the confirm panel narrower than content
   dialogs.
2. **SelectTrigger** (`src/components/ui/Select.tsx`) — `rounded-md` →
   `rounded-lg` and `focus:ring` → `focus-visible:ring-2 focus-visible:ring-ring/50
   focus-visible:border-ring`, matching the Input/Button focus-ring language.
3. **DialogTitle / DialogDescription** (`src/components/ui/Dialog.tsx`) —
   were unstyled Radix passthroughs; now carry `text-lg font-semibold
   text-foreground` and `text-sm text-muted-foreground` respectively, so
   every dialog heading/body renders in the design-system type scale.
4. **TaskDetailModal link buttons** (`src/components/tasks/TaskDetailModal.tsx`)
   — raw `<button className="text-primary …">` (parent task + dependency
   rows) replaced with `<Button variant="link">`, the shared link-button
   style.
5. **TaskFormModal footer** (`src/components/tasks/TaskFormModal.tsx`) —
   removed the extra `<div className="flex gap-4">` wrapper inside
   `DialogFooter`; the submit/cancel buttons are now direct children, the
   same as every other dialog footer.

Also from the previous session: `scripts/capture-screenshots.mjs` (standalone
Playwright capture script with deterministic mock-state injection via
`docs/screenshots/.mock-state.json`), `scripts/verify-consistency.mjs`, the
11 before-shots, and the `scripts/` exclusion in `eslint.config.cjs`.

### Fixed in this session

1. **Reverted `src/api/interceptors/mocks.ts` to HEAD.** The previous session
   had loosened the mock login to accept any credentials. That broke the
   `login with invalid credentials shows error` e2e test (the mock no longer
   rejects, so the error banner never appears). The change was also
   unnecessary: the capture script already logs in with the original mock
   credentials (`test@example.com` / `password123`). Reverting restores the
   rejection path and the test passes.
2. **`playwright.config.ts` — `actionTimeout: 200` → `2000`.** The 200 ms
   action budget was the root cause of 7 failing tests (6 of them already
   failing on HEAD — verified by stashing the changes and running the suite
   against a clean checkout). Dialog clicks start their 200 ms budget before
   the dialog is mounted; mount latency plus the 150 ms `dialog-in` entry
   animation (the shared Dialog's, now also applied to ConfirmDialog)
   regularly exceeded the budget, so Playwright reported "waiting for
   element to be visible, enabled and stable" timeouts on perfectly
   actionable buttons. This is the most likely cause of the original
   crash: the previous session sat in a retry loop on these failures.
3. **`playwright.config.ts` — `workers: 2`.** The default (cores/2 = 3)
   workers plus the shared dev server and ~7.5 GB available RAM made cold
   `page.goto` calls hit the 10 s navigation timeout intermittently.
4. **Removed stale `playwright-report/` and `tests/test-results/`** —
   gitignored artifacts left by the crashed run's test session. `pnpm lint`
   was scanning their minified trace assets and reporting 3053 errors.
5. **Re-captured the 11 after-shots** against the final code (after the
   mocks.ts revert) with `node scripts/capture-screenshots.mjs after`, so
   `docs/screenshots/after/` is exact evidence of the shipped state.

## Deviation from the plan (disclosed)

The plan covered the 5 design fixes, the screenshots, and the
build/lint/test self-checks. The `playwright.config.ts` changes
(`actionTimeout`, `workers`) are a deviation: the self-check surfaced that
the e2e suite was failing on HEAD in this environment (200 ms action
timeout + 3 workers under container load), so the suite infrastructure had
to be repaired for the self-check — and the downstream test step — to be
meaningful. No app-source behavior was changed beyond the 5 planned fixes.
