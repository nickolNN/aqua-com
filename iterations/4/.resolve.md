# Resolve — iteration 4

## What was done

The Test step (iteration 3) passed the app itself in every browser
scenario and recorded one minor defect (F1): the shipped verifier
`scripts/verify-consistency.mjs` has a timing-dependent rich-task link
check (fixed `waitForTimeout(600)` after `page.goto`) that fails under
dev-server load. This iteration closed that defect — script-only, no app
edits, no re-captures.

### 1. Fixed sleeps replaced with DOM waits

All five fixed `waitForTimeout` sleeps are gone. Each check now waits on
the exact element it reads:

- detail modal: the dialog heading + the `DialogDescription` `<p>`;
- ConfirmDialog: its `h2` + first button, and `detached` state after
  Cancel;
- rich-task detail: `page.getByRole('button', { name: 'View parent task' })
  .waitFor()` (the exact fix the Test step prescribed);
- create-task modal: the first combobox (`.first()` — the dialog carries
  two: Priority and Status).

### 2. Graceful SKIP for the no-rich-task case

The `check` helper gained a `skip` flag (reported as `SKIP`, excluded from
the pass denominator). When the pinned board has no task with both a
parent and a dependency, the two link-action checks are skipped instead
of failing — a no-rich-task board is a valid state, not a defect.

### 3. Root cause found and fixed: the board pin was silently dead

While verifying the new waits, the runs kept showing a *different* random
board every run (fresh task UUIDs in the link labels). Investigation
proved the pinning `addInitScript` had never worked: its body closed over
`TASKS_STORAGE_KEY`, a Node-side const. Playwright stringifies the init
script function and re-evaluates it in the browser, where that variable
does not exist — a silent `ReferenceError`, so the pin write never
landed, `localStorage` stayed empty, and the app seeded a fresh random
board on every run. The flaky check was therefore racing two things, not
one: the render timing *and* a non-deterministic board.

Fix: the init script now uses the literal `'mock_data_tasks'` key, with a
comment documenting the no-closure constraint. After the fix, the link
label is byte-identical across runs (`start_to_start -
ed333243-9ab2-4b15-9b89-4f9dbe0eb127`) — the board is genuinely pinned.

### 4. Summary line

The final summary now reports `N/M checks passed (K skipped)`, counting
skipped checks separately from failures.
